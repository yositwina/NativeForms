# TwinaForms Test Environment - API, OAuth, SAML, and Agentforce Access

Date: 2026-08-24

Package version: `0.14.0.1`

Subscriber Package Version ID: `04tgL000000OO9FQAW`

## Summary

TwinaForms uses Salesforce OAuth and AWS-hosted runtime APIs, but reviewers do not need manually supplied API keys, OAuth access tokens, OAuth refresh tokens, SAML assertions, AWS credentials, tenant secrets, or HMAC signing secrets.

Reviewer access is performed through the supplied Salesforce test org credentials. Reviewers can establish or verify OAuth connection on the TwinaForms Connect page, and package-to-AWS service flows are generated by the installed TwinaForms package.

## Reviewer Test Walkthrough

No external API keys, OAuth tokens, or secrets are required.

1. Log in to the Salesforce test org as the System Administrator test user.
2. Open the TwinaForms app.
3. Open the Connect page and verify or complete the Salesforce OAuth connection.
4. Click Install demo records if demo records are not already installed.
5. Open Designer and create a form directly, import a Salesforce page layout, or use an existing demo form.
6. Publish the form and open the public form URL.
7. Test prefill with a sample Contact email parameter if the form is configured for prefill.
8. Test submit and confirm the expected Salesforce record change.
9. Review Submission Logs in the TwinaForms app.
10. Optional connected-org test: connect another Salesforce org from TwinaForms setup, publish a form in the source org, then import the latest published connected snapshot as a Draft in the target org.
11. Optional Agentforce test: ask Agentforce to create a TwinaForms form from a Salesforce page layout. Confirm that it creates a Draft form and returns a Designer URL for review.

## Salesforce OAuth

TwinaForms connects a subscriber Salesforce org to AWS through Salesforce OAuth authorization code flow.

The OAuth flow is initiated from inside Salesforce. A reviewer opens the TwinaForms Connect page in the installed Salesforce package and clicks the connect action. The package prepares non-secret subscriber org setup context, such as the Salesforce org id, admin email, company name, and Salesforce login base URL, and opens the TwinaForms AWS connect endpoint.

The initial AWS connect endpoint only starts the OAuth setup flow. AWS does not treat this pre-OAuth context as authentication, and it does not grant access to Salesforce data, AWS data, tenant secrets, or protected package service APIs.

AWS redirects the reviewer to Salesforce OAuth authorization. After authorization, AWS receives the OAuth callback, exchanges the authorization code server-to-server, and validates that the Salesforce org id returned by OAuth matches the org id from the setup request. Only after this validation does AWS store the org-specific connection in AWS Secrets Manager.

No manual OAuth token is provided to reviewers. AWS exchanges the OAuth authorization code server-to-server and stores the Salesforce refresh token in AWS Secrets Manager. Tokens are not exposed in the browser, public form HTML, Salesforce custom objects, or reviewer documentation.

## Package-to-AWS Service Access

After OAuth connection, TwinaForms creates or retrieves a private per-org signing secret. Later package-to-AWS service calls are signed internally by Apex using HMAC.

Access details:

- No API key is required.
- No manual bearer token is required.
- No SAML login is required.
- No AWS IAM user is required.
- Package-to-AWS calls are generated by the installed managed package.
- Signed requests include org id, timestamp, nonce, body hash, and HMAC signature headers.
- AWS validates the signature, org context, timestamp window, and nonce before accepting protected package service calls.

## Public Form Runtime Access

Published TwinaForms forms are public browser pages. Public form users do not authenticate with Salesforce.

Runtime access details:

- Public form host: `https://forms.twinaforms.com`
- Public prefill endpoint: AWS Lambda Function URL, called by the published form.
- Public submit endpoint: AWS Lambda Function URL, called by the published form.
- Public runtime authentication: per-form publish token embedded in the generated form and validated server-side by AWS.

The public form publish token is not a Salesforce OAuth token, not an AWS credential, and not a tenant administration token. It gates only the public prefill and submit endpoints for that specific published form. AWS stores only a hash of the publish token with the server-side form policy.

## Connected-Org Import/Export Access

Connected-org import/export uses package-to-AWS service access, not public form access.

Reviewer access details:

- Connect another org from the TwinaForms setup area.
- Publish a form in the source org.
- Open Designer in the target org and choose import from connected org.
- Select a latest published snapshot.
- Review the import preview.
- Import creates a Draft version.

Connected-org portable snapshot APIs reject unauthenticated requests. The August ZAP report `07-portable-snapshots-import-export.html` verifies that the tested routes return `401 Unauthorized` when called without bearer credentials.

## Agentforce

TwinaForms includes an Agentforce-compatible Apex invocable action:

- `Create TwinaForms Form from Page Layout`

The action lets Agentforce create a Draft TwinaForms form from a Salesforce object page layout. If multiple layouts exist, the action returns layout choices and asks the user to choose one. The action returns a Designer URL for admin review.

The action does not publish forms automatically and does not expose AWS credentials, OAuth refresh tokens, tenant secrets, or public form publish tokens.

## SAML

TwinaForms does not require SAML access for reviewer testing.

## Security Notes

- Salesforce OAuth refresh tokens are stored only in AWS Secrets Manager.
- Public browsers never receive Salesforce OAuth refresh tokens.
- Public browsers never receive the private per-org package signing secret.
- Public browsers never receive AWS credentials.
- Public browsers never receive executable Salesforce command definitions.
- AWS runtime APIs validate form id, publish token hash, and server-side form policies before performing Salesforce reads or writes.
- Connected-org snapshot APIs validate package-to-AWS service trust and connected-org group membership.
- Agentforce-created forms are Drafts and require normal admin review before publish.
