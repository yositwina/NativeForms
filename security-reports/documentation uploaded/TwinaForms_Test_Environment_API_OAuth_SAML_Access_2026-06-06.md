# TwinaForms Test Environment - API, OAuth, and SAML Access

Date: 2026-06-06

## Summary

TwinaForms uses Salesforce OAuth and AWS-hosted runtime APIs, but reviewers do not need manually supplied API keys, OAuth access tokens, OAuth refresh tokens, SAML assertions, AWS credentials, or tenant secrets.

Reviewer access is performed through the supplied Salesforce test org credentials. Reviewers can establish OAuth connection on connect page and the package-to-AWS service flows from the installed TwinaForms package.

## Reviewer Test Walkthrough

No external API keys, OAuth tokens, or secrets are required.

1. Open the TwinaForms app → **Connect** page → authorize the org via Salesforce OAuth.
2. On the Connect page, click **Install demo records** — this creates a theme and two sample forms ("Contact details update demo" and "Prefill multi record demo").

Exercise the runtime end-to-end:

3. Open the **Designer**, open the first sample form, and click **Publish**. You get a public form URL, e.g. `https://forms.twinaforms.com/twinaforms-8rc9/form1`.
4. **Test prefill:** open the published form with a known Contact email as a URL parameter:
   `https://forms.twinaforms.com/twinaforms-8rc9/form1?email=liam.carter@example.com`
   The fields pre-populate from the matching Contact.
5. **Test submit:** complete the form (solve the CAPTCHA) and submit. Confirm in Salesforce that the Contact was created or updated and a **Submission Logs** entry appears.

## Salesforce OAuth

TwinaForms connects a subscriber Salesforce org to AWS through a Salesforce OAuth authorization flow.

The OAuth flow is initiated from inside Salesforce. A reviewer opens the TwinaForms Connect page in the installed Salesforce package and clicks the connect action. The package prepares subscriber org setup context, such as the Salesforce org id, admin email, company name, and Salesforce login base URL, and opens the TwinaForms AWS connect endpoint.

The initial AWS connect endpoint is intentionally public because it only starts the OAuth setup flow and accepts non-secret setup context. AWS does not treat this pre-OAuth context as authentication, and it does not grant access to Salesforce data, AWS data, tenant secrets, or protected package service APIs.

AWS then redirects the reviewer to Salesforce OAuth authorization. After authorization, AWS receives the OAuth callback, exchanges the authorization code server-to-server, and validates that the Salesforce org id returned by OAuth matches the org id from the setup request. If the org ids do not match, AWS rejects the connection. Only after this validation does AWS store the org-specific connection in AWS Secrets Manager.

Instructions:

1. Log in to a Salesforce test org as the System Administrator test user.
2. Open the TwinaForms app.
3. Open the TwinaForms Connect page.
4. If the org is already connected, verify the connection status.
5. If reconnection is required, click the Connect or reconnect action and complete the Salesforce OAuth authorization prompt.

No manual OAuth token is provided to reviewers. AWS exchanges the OAuth authorization code server-to-server and stores the Salesforce refresh token in AWS Secrets Manager. Tokens are not exposed in the browser, public form HTML, Salesforce custom objects, or reviewer documentation.

## Package-to-AWS Service Access

After OAuth connection, TwinaForms creates or retrieves a private per-org signing secret. Later package-to-AWS service calls are signed internally by Apex using HMAC.

Access details:

- No API key is required.
- No manual bearer token is required.
- No SAML login is required.
- No AWS IAM user is required.
- Package-to-AWS calls are generated by the installed managed package.
- Signed requests include org id, timestamp, nonce, body hash, and HMAC signature headers.
- AWS validates the signature, org context, timestamp window, and nonce before accepting protected package service calls.

## Public Form Runtime Access

Published TwinaForms forms are public browser pages. Public form users do not authenticate with Salesforce.

Runtime access details:

- Published form URL: `https://forms.twinaforms.com/twinaforms-8rc9/form1`
- Public form host: `https://forms.twinaforms.com`
- Public prefill endpoint: AWS Lambda Function URL, called by the published form.
- Public submit endpoint: AWS Lambda Function URL, called by the published form.
- Public runtime authentication: per-form publish token embedded in the generated form and validated server-side by AWS.

The public form publish token is not a Salesforce OAuth token, not an AWS credential, and not a tenant administration token. It gates only the public prefill and submit endpoints for that specific published form. AWS stores only a hash of the publish token with the server-side form policy.

## SAML

TwinaForms does not require SAML access for reviewer testing.

## Security Notes

- Salesforce OAuth refresh tokens are stored only in AWS Secrets Manager.
- Public browsers never receive Salesforce OAuth refresh tokens.
- Public browsers never receive the private per-org package signing secret.
- Public browsers never receive AWS credentials.
- Public browsers never receive executable Salesforce command definitions.
- AWS runtime APIs validate form id, publish token hash, and server-side form policies before performing Salesforce reads or writes.
